# 整理技术文档 - 参考

与 [SKILL.md](SKILL.md) 配合使用，提供扩展模板与边界情况说明。

## 其他文档类型

### 变更日志 (CHANGELOG)

- 按版本倒序（新版本在上）
- 每版本下分：Added / Changed / Fixed / Deprecated 等（Keep a Changelog 风格）
- 日期格式统一（如 YYYY-MM-DD）

### 贡献指南 (CONTRIBUTING)

- 如何克隆、分支、提 PR
- 代码风格与提交信息约定
- 测试与 CI 要求

### 部署 / 运维文档

- 环境要求与依赖
- 部署步骤（含命令与顺序）
- 配置项说明与敏感信息处理提醒
- 健康检查与常见问题

## 多文档时的整理策略

1. **先定入口**：确定主 README 或 `docs/README.md` 为入口，其它文档在入口中有链接。
2. **避免重复**：通用内容（如「如何运行」）只在一处写细，其它处用链接引用。
3. **命名一致**：文件名与标题对应（如 `api.md` ↔「API 说明」），便于记忆和链接。

## 与现有规范冲突时

- 若项目已有 `.cursor/rules` 或 `docs/` 下的规范，整理结果不得违反其中对标题层级、术语、文件命名的要求。
- 若用户明确说「按 XX 规范来」，以用户指定为准，并在输出中注明所依规范。
